# Отчет по техническому аудиту и функциональному анализу веб-ресурсов (Конкурентов)

## 1. Kinopio

* **Название ресурса / компании:** Kinopio
* **Адрес ресурса в сети:** [https://kinopio.club/](https://kinopio.club/)

### 1.1. Функционал для конечного пользователя
Kinopio представляет собой визуальное пространство для пространственного мышления, ведения заметок, брейншторминга и планирования:
* **Spatial Canvas (Пространственный холст):** Свободное размещение заметок, карточек, списков и связей на бесконечной доске.
* **Мультимедийная интеграция:** Прямая вставка изображений, GIF-анимаций, аудио- и видеофайлов на холст.
* **Кастомизация и оформление:** Поддержка выбора эмодзи, кастомных фонов доски, цветовых тегов и настройки связей между объектами.
* **Коллаборация:** Совместное редактирование в реальном времени, возможность делиться досками по ссылке или экспортировать их.

### 1.2. Анализ архитектуры и логики
* **Архитектурный подход:** Single Page Application (SPA).
* **Фронтенд-стек:** Vue.js (с использованием Pinia/Vuex для управления состоянием, инициатор `useApiStore.js`).
* **Взаимодействие с сервером:** REST API с использованием `fetch` и асинхронных запросов (`XDR/Fetch`).
* **Особенности:** Клиентоориентированная логика рендеринга с фоновой отправкой телеметрии и событий через эндпоинты вида `/analytics-event`.

### 1.3. Семантика HTML5
Использование семантических элементов в структуре страницы:

| Элемент HTML5 | Количество | Применение в интерфейсе |
| :--- | :--- | :--- |
| `<header>` | 1 шт. | Верхняя панель навигации и логотип |
| `<nav>` | 3 шт. | Списки ссылок и меню управления |
| `<main>` | 1 шт. | Основная область холста (Canvas) |
| `<section>` | 0 шт. | Не используется в текущей разметке |
| `<article>` | 0 шт. | Не используется в текущей разметке |
| `<aside>` | 25 шт. | Боковые панели, плавающие плашки, инструменты и карточки |
| `<footer>` | 1 шт. | Подвальная область с технической информацией |

**Вывод по семантике:** Основной каркас приложения разложен по ключевым тегам HTML5 (`header`, `main`, `footer`, `nav`). Обилие элементов `<aside>` обусловлено спецификой Canvas-интерфейса, где панели управления выступают как вспомогательные плавающие блоки.

### 1.4. Анализ верстки и семантика классов (`div`-верстка)
* **Наличие `div`-верстки:** Разметка оберток и внутренних компонентов выполнена преимущественно с помощью `<div>`.
* **Примеры семантических классов:**
  * `.footer-wrap` — внешняя обертка футера;
  * `.space-zoom` — блок управления масштабом рабочей области доски;
  * `.button-wrap` / `.footer-button-wrap` — обертки элементов управления и кнопок;
  * `.left`, `.right` — флекс-контейнеры позиционирования.

### 1.5. Адаптивность ресурса
* **Media-запросы и CSS:** CSS Flexbox (`display: flex`) и CSS variables.
* **Адаптивные функции:** Использование CSS-функций `max(0px, env(safe-area-inset-bottom))` для адаптации под устройства с программными вырезами ("челками") и нижними панелями навигации.

### 1.6. Анализ с помощью Lighthouse
* **Условия проверки:** Мобильный интернет, Десктоп (Desktop), Домашнее/Тестовое окружение.
* **Результаты аудита:**
  * **Performance (Производительность):** 67 / 100 *(задержки мобильного соединения при загрузке тяжелых клиентских JS-скриптов)*
  * **Accessibility (Доступность):** 72 / 100
  * **Best Practices (Лучшие практики):** 96 / 100
  * **SEO (Поисковая оптимизация):** 77 / 100

### 1.7. Использование локального хранилища и Cookies
* **Local Storage:** Хранилище пустое (`length: 0`).
* **Cookies:** Технический флаг (`true`) на домене `kinopio.club` для фиксации состояния сессии без сохранения персональных данных.

### 1.8. Маркетинговые инструменты и аналитика
* **Внешние трекеры:** Сторонние тяжелые системы аналитики (Google Analytics, Yandex Metrika, Facebook Pixel, Hotjar) отсутствуют.
* **Собственная аналитика:** Отправка `POST`-запросов к собственному эндпоинту `analytics-event` (через инициатор `useApiStore.js`).

## 2. tldraw

* **Название ресурса / компании:** tldraw
* **Адрес ресурса в сети:** [https://www.tldraw.com/](https://www.tldraw.com/)

### 2.1. Функционал для конечного пользователя
tldraw — это виртуальная доска с упором на скорость работы и векторное рисование:
* **Векторное рисование и скетчинг:** Инструменты свободного рисования от руки, автокоррекция геометрических фигур, стрелок и линий.
* **Работа со слоями и элементами:** Выделение, группировка, блокировка, дублирование и трансформация объектов на бесконечном холсте.
* **Текстовые заметки и фигуры:** Добавление стикеров, текстовых блоков, стандартных геометрических примитивов.
* **Мгновенная совместная работа:** Поддержка создания комнат с генерацией публичной ссылки для совместного рисования без обязательной регистрации.
* **Локальная автономность:** Поддержка офлайн-режима и локального сохранения всех проектов прямо в браузере.

### 2.2. Анализ архитектуры и логики
* **Архитектурный подход:** Single Page Application (SPA).
* **Фронтенд-стек:** React (приложение монтируется в DOM-дерево в элемент `<div id="root">`). Для аутентификации используется сервис Clerk (`__clerk_environment`, `clerk-components`).
* **Взаимодействие с сервером:** Асинхронный обмен данными для синхронизации локального состояния холста с облачным хранилищем, загрузка веб-виталов (`web-vitals.js`) и скриптов аналитики.
* **Особенности:** Холст автономно сохраняет состояние документов локально в памяти браузера.

### 2.3. Семантика HTML5
Использование семантических элементов в структуре страницы:

| Элемент HTML5 | Количество | Применение в интерфейсе |
| :--- | :--- | :--- |
| `<header>` | 1 шт. | Скрытый заголовок приложения для доступности (`<h1 class="visually-hidden">`) |
| `<nav>` | 0 шт. | Не используется в текущей разметке |
| `<main>` | 0 шт. | Не используется в текущей разметке |
| `<section>` | 0 шт. | Не используется в текущей разметке |
| `<article>` | 0 шт. | Не используется в текущей разметке |
| `<aside>` | 0 шт. | Не используется в текущей разметке |
| `<footer>` | 0 шт. | Не используется в текущей разметке |

**Вывод по семантике:** Почти полное отсутствие семантических тегов HTML5 во внешнем DOM-дереве. Весь графический редактор отрисовывается внутри единого React-контейнера `<div id="root">`. Тег `<header>` используется чисто функционально для доступности.

### 2.4. Анализ верстки и семантика классов (`div`-верстка)
* **Наличие `div`-верстки:** Приложение построено полностью на основе `<div>`-оберток.
* **Примеры семантических классов:**
  * `.visually-hidden` — утилитарный класс для скрытия текстовых элементов от визуального отображения (для скринридеров);
  * `.tla`, `.tl-container` — основные обертки контекста tldraw;
  * `.tla-theme-container`, `.tla-theme__light`, `.tl-theme__light` — классы управления цветовой темой интерфейса.

### 2.5. Адаптивность ресурса
* **Media-запросы и CSS:** CSS Flexbox (`display: flex`) и динамические темы (`data-theme="light"`).
* **Адаптивные функции:** В локальном хранилище отслеживаются флаги состояния мобильного интерфейса (`isSidebarOpenMobile`). Интерфейс динамически масштабирует панели инструментов под размер экрана.

### 2.6. Анализ с помощью Lighthouse
* **Условия проверки:** Мобильный интернет, Десктоп (Desktop), Домашнее/Тестовое окружение.
* **Результаты аудита:**
  * **Performance (Производительность):** 69 / 100 *(инициализация тяжелого движка холста React и загрузка внешних скриптов)*
  * **Accessibility (Доступность):** 100 / 100 *(благодаря скрытым элементам доступности)*
  * **Best Practices (Лучшие практики):** 77 / 100
  * **SEO (Поисковая оптимизация):** 100 / 100 *(идеальная базовая мета-разметка)*

### 2.7. Использование локального хранилища и Cookies
* **Local Storage:**
  * `TLDRAW_DOCUMENT_v2...` / `TLDRAW_DEFAULT_DOCUMENT_NAME_v2` — индекс и имя текущего документа;
  * `TLDRAW_USER_DATA_v3` — пользовательские настройки (`id`, цвет);
  * `tldrawapp_session_3` — состояние текущей сессии;
  * `tldraw_cookie_consent` — статус согласия на сбор аналитики;
  * `__clerk_environment` — параметры окружения аутентификации Clerk;
  * `ph_phc_..._posthog` — идентификаторы пользователя и сессии PostHog.
* **Cookies:**
  * `__cf_bm`, `_cfuvid` — файлы куки защиты Cloudflare;
  * `__client`, `__client_uat` — сессионные куки сервиса Clerk;
  * `_ga`, `_ga_QK4E79381S` — аналитические куки Google Analytics;
  * `ph_phc_...` — куки отслеживания PostHog.

### 2.8. Маркетинговые инструменты и аналитика
* **Внешние сервисы аналитики:**
  * **PostHog:** проксируемая аналитика на поддомене `analytics.tldraw.com` (скрипты `config.js` и `web-vitals.js`);
  * **Google Tag Manager / Google Analytics:** интеграция через `gtag/js?id=G-QK4E79381S`;
  * **Clerk:** сервис аутентификации и трекинга пользователей.

## 3. OmniCanvas (OmniCanvas Notes)

* **Название ресурса / компании:** OmniCanvas (OmniCanvas Notes)
* **Адрес ресурса в сети:** [https://app.omnicanvasnotes.com/](https://app.omnicanvasnotes.com/)

### 3.1. Функционал для конечного пользователя
OmniCanvas комбинирует инструменты гибридных заметок и визуальной интеллект-карты:
* **Интеграция с Excalidraw:** Использование движка Excalidraw для работы со схемами и набросками.
* **Древовидная/иерархическая структура заметок:** Организация заметок с возможностью быстрого переключения между списковым видом и визуальным отображением на холсте.
* **Поддержка Markdown:** Ведение текстовых заметок с форматированием кода, списков и заголовков.
* **Управление пространствами (Workspaces):** Создание изолированных пространств под разные сценарии (например, `brainstorm`).

### 3.2. Анализ архитектуры и логики
* **Архитектурный подход:** Single Page Application (SPA).
* **Фронтенд-стек:** React (приложение инициализируется через клиентский каркас с `Boot shell`, рендерится внутри `<div id="root">`), **Tailwind CSS** и графический движок **Excalidraw**.
* **Взаимодействие с сервером:** Клиентский рендеринг рабочей области пространственных заметок и холста, локальная синхронизация состояния.

### 3.3. Семантика HTML5
Использование семантических элементов в структуре страницы:

| Элемент HTML5 | Количество | Применение в интерфейсе |
| :--- | :--- | :--- |
| `<header>` | 1 шт. | Верхняя семантическая панель навигации/шапки |
| `<nav>` | 0 шт. | Не используется в текущей разметке |
| `<main>` | 1 шт. | Основная область взаимодействия и холста (`flex-1 relative overflow-hidden`) |
| `<section>` | 2 шт. | Внутренние секционные блоки холста и интерфейса |
| `<article>` | 0 шт. | Не используется в текущей разметке |
| `<aside>` | 1 шт. | Боковая панель списка заметок и навигации (`border-r flex flex-col`) |
| `<footer>` | 1 шт. | Техническая подвальная часть |

**Вывод по семантике:** OmniCanvas демонстрирует грамотную семантическую структуру для SPA-редактора: внешние контейнеры четко разделены тегами `<aside>` (боковая панель управления) и `<main>` (рабочая область редактирования).

### 3.4. Анализ верстки и семантика классов (`div`-верстка)
* **Наличие `div`-верстки:** Использование utility-first CSS (Tailwind CSS).
* **Примеры классов (Tailwind CSS):**
  * `fixed inset-0 flex overflow-hidden pl-[env(safe-area-inset-left)]` — полноэкранная фиксация с адаптивными отступами;
  * `bg-slate-900 text-slate-100` — селекторы цветовой темы;
  * `custom-scrollbar` — кастомное оформление полосы прокрутки;
  * `role="tablist"` — ARIA-атрибуты для обеспечения доступности вкладок.

### 3.5. Адаптивность ресурса
* **Media-запросы и CSS:** Применение адаптивных брейкпоинтов Tailwind CSS (`lg:block`, `lg:relative`, `lg:w-auto`).
* **Адаптивные функции:** Использование CSS-переменных окружения `env(safe-area-inset-left)` и `env(safe-area-inset-right)`. Боковая панель `<aside>` автоматически трансформируется из фиксированного выезжающего меню (`w-[85vw] max-w-[300px]`) на мобильных экранах в относительный статичный блок на десктопе (`lg:relative`).

### 3.6. Анализ с помощью Lighthouse
* **Условия проверки:** Мобильный интернет, Десктоп (Desktop), Домашнее/Тестовое окружение.
* **Результаты аудита:**
  * **Performance (Производительность):** 76 / 100 *(загрузка и инициализация модуля Excalidraw и скриптов React)*
  * **Accessibility (Доступность):** 93 / 100 *(благодаря ARIA-ролям и семантическим тегам)*
  * **Best Practices (Лучшие практики):** 96 / 100
  * **SEO (Поисковая оптимизация):** 50 / 100 *(ограничения закрытого SPA-интерфейса)*

### 3.7. Использование локального хранилища и Cookies
* **Local Storage:**
  * `oc_anon_id` — анонимный идентификатор пользователя;
  * `oc_onboarding_intent` — сохраненный сценарий первично выбранного использования (`brainstorm`);
  * `omnicanvas_dark_mode` — флаг темы оформления (`true`);
  * `omnicanvas_device_id` — уникальный GUID устройства;
  * `omnicanvas_excalidraw_library` — локально сохраненная библиотека стикеров и компонентов Excalidraw;
  * `omnicanvas_recent_notes` / `omnicanvas_workspace_modes_v1` — списки последних заметок и режимы отображения пространств.
* **Cookies (Cloudflare Zaraz & Analytics):**
  * `cf_zaraz_client` / `cfz_zaraz-analytics` — системные куки менеджера Cloudflare Zaraz;
  * `cfz_google-analytics_v4` / `cfzs_google-analytics_v4` — проксированные куки Google Analytics v4;
  * `oc_anon_id` / `oc_attr` — идентификаторы анонимной сессии и источника перехода (`referrer`).

### 3.8. Маркетинговые инструменты и аналитика
* **Маркетинг и аналитика (Cloudflare Zaraz):** Внешние трекеры маскируются и проксируются через серверную среду **Cloudflare Zaraz** (указано в названии куки `cf_zaraz...` и `cfz_google-analytics_v4`). Google Analytics 4 исполняется не напрямую с клиента, что позволяет обходить блокировщики рекламы.

## 4. Сравнительные выводы и рекомендации к внедрению

### 4.1. Сводный анализ конкурентов
1. **Kinopio:** Отличается уникальным подходом к работе с медиа-контентом и нестандартной семантикой (25 тегов `<aside>`), но имеет более низкую производительность на мобильных сетях.
2. **tldraw:** Лидер по UX и отзывчивости векторного рисования. Демонстрирует идеальную доступность (100 Accessibility) и максимальную локальную автономность (активная работа с LocalStorage), но практически не использует семантические HTML5-теги в DOM-дереве.
3. **OmniCanvas:** Построен на базе Tailwind CSS и движка Excalidraw. Обладает самой сбалансированной HTML5-семантикой из всех трех сервисов и маскирует аналитику через Cloudflare Zaraz.

### 4.2. Рекомендации по интеграции функций в собственный проект

* **Из tldraw (ПРИОРИТЕТ: ВЫСОКИЙ):**
  * **Функционал:** Внедрить возможность свободного рисования и векторного скетчинга от руки напрямую на холсте (Canvas).
  * **Обоснование:** Это базовый инструмент для проектирования и визуального брейншторминга, обеспечивающий высокий показатель вовлеченности (User Engagement) и гибкость при создании быстрых набросков.

* **Из Kinopio (ПРИОРИТЕТ: НИЗКИЙ):**
  * **Функционал:** Внедрить возможность прямого размещения мультимедиа-контента (GIF-анимации, изображения, аудио, видео) непосредственно на холст без обязательного создания отдельной текстовой ноды/заметки.
  * **Обоснование:** Повышает удобство составления мудбордов и визуальных заметок, однако является вторичной фичей по отношению к базовому графическому и текстовому функционалу.

* **Из OmniCanvas:**
  * Дополнительных уникальных фич для внедрения не выявлено (сервис использует стандартную связку React + Excalidraw + Tailwind).
