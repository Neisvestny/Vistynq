# Vistynq — функциональные требования

Версия: 2026-11-13 · Источник правды по поведению: [`ui-ux.md`](ui-ux.md) и [`user-guide.md`](user-guide.md).
Связь с планом работ — [`ROADMAP.md`](ROADMAP.md) и [`TODO.md`](TODO.md), контракт API — [`api.md`](api.md) / `openapi.yaml`.

> **Vistynq** — веб-приложение для работы с заметками как с графом знаний: каждая заметка — нода на
> бесконечном канвасе, заметки связаны прямыми и косвенными ссылками, навигация строится на тегах,
> важности и наглядных связях.

## Роли и модель доступа

| Термин | Описание |
|---|---|
| Гость (аноним) | Видит только публичные shared-страницы (публичные заметки публичных канвасов), только чтение. |
| Пользователь | Зарегистрированный и подтвердивший email (без подтверждения войти нельзя). |
| Владелец канваса | Создатель канваса. Полные права на канвас и все его заметки; единственный, кто переименовывает и удаляет канвас, выдаёт доступы и меняет уровень доступа канваса. |
| Автор заметки | Создатель заметки (владелец канваса или editor). Полные права на свою заметку; управляет её видимостью и доступами. Автор и владелец — один и тот же человек для своего ресурса. |
| Editor | Роль по выдаче; одна и та же для канваса и заметки, различается область. Editor канваса: двигает ноды, создаёт и редактирует публичные заметки, ссылки, теги, архив. Editor заметки: правит только эту заметку. |
| Viewer | Роль по выдаче; только просмотр. |

**Доступ к канвасу:** `private` (владелец и те, кому выдан доступ) или `public` (любой по ссылке, только чтение). По умолчанию — `private`.
**Видимость заметки:** `public` (по умолчанию; видна всем, у кого есть доступ к канвасу) или `private` (только автор, владелец канваса и те, кому выдан доступ на эту заметку).
Выдать доступ можно по email: если аккаунт уже есть — доступ **мгновенный**; если нет — после регистрации и подтверждения email.
Недоступный контент не отображается никак (в т.ч. ссылки на него) и отвечает 404; если ресурс виден, но прав не хватает — 403.

## Функциональные требования (FR)

Приоритеты: **P0** — критично · **P1** — важно · **P2** — желательно · **P3** — на будущее.
Ссылки на задачи roadmap указаны в скобках `(R##)`.

### 1. Аккаунты и авторизация

1. **FR-01. Регистрация (P0, R10).** Регистрация по email, паролю (≥ 8 символов) и имени. Письмо со
   ссылкой подтверждения; без подтверждения войти нельзя. Повторная отправка письма («Отправить
   ещё раз»).
2. **FR-02. Вход и сессия (P0, R10/R11).** Вход по email + пароль (argon2id). Access-JWT (TTL ~15 мин)
   хранится в памяти клиента, refresh — в httpOnly cookie. Прозрачный авто-refresh сессии; при повторном
   401 — выход с сообщением «Сессия истекла». Логин ограничен rate-limit.
3. **FR-03. Безопасность сессий (P1, R11).** SHA-256-хэш refresh-токенов в БД, ротация с family-группой;
   повторное использование старого refresh отзывает всё семейство. Cookie-флаги: HttpOnly, Secure
   (по env), SameSite=Lax.
4. **FR-04. Восстановление пароля (P1, R11).** «Забыли пароль?» → письмо → смена пароля. Сброс всех
   активных refresh-токенов пользователя.
5. **FR-05. Профиль (P1, R10/R17/R23/R31).** Просмотр и изменение имени; смена email с подтверждением
   нового адреса (старый действует до подтверждения); аватар. Выход отзывает токены браузера.

### 2. Канвасы

6. **FR-06. CRUD канвасов (P1, R12/R23).** Список канвасов на дашборде (карточки: название, дата изменения,
   количество доступных заметок, бейдж роли, бейдж «публичный»), включая канвасы, к которым выдан доступ.
   Создание/открытие канваса. Название меняет и канвас удаляет **только владелец**; удаление безвозвратное
   (hard-delete с каскадом).
7. **FR-07. Загрузка графа (P1, R12).** Канвас целиком отдаётся одним запросом `/graph` (без N+1) с
   фильтрацией по правам (пользователь видит только доступные ноды и рёбра).

### 3. Заметки

8. **FR-08. Манифест и тело (P1, R13/R28).** Заметка = манифест (заголовок, важность 1–5, теги,
   актуальность, видимость) + markdown-тело. Манифест редактируется формой (не как код), тело — редактором.
   Сохранение — по кнопке (автосохранение — не v1, ui-ux §3).
9. **FR-09. Позиционирование (P2, R13/R26).** Позиция и размер ноды сохраняются после drag/resize (PATCH с
   дебаунсом ~500 мс) и восстанавливаются при перезагрузке.
10. **FR-10. Жизненный цикл (P1, R13/R29).** soft-delete → панель «Удалённые» (восстановить в прежнюю
    позицию / purge необратимо). «Неактуально» → архив «Неактуальные» (вернуть / удалить).
    Пометка «ссылка удалена» у косвенных ссылок после purge — только для имеющих доступ.

### 4. Теги

11. **FR-11. Теги канваса (P1, R14/R27).** Теги локальны для канваса, имеют цвет. Создание, переименование,
    перекраска, удаление (editor канваса и выше). Назначать теги заметке может и editor заметки. Удаление
    тега затрагивает все помеченные заметки (с подтверждением).
12. **FR-12. Фильтры и подсветка (P2, R27).** Hover по тегу подсвечивает ноды (остальные — затемнены).
    Фильтр важности 1–5 (локально, без изменения БД) + тумблер «Показывать неактуальные».

### 5. Ссылки

13. **FR-13. Прямые ссылки (P2, R15/R30).** Связь, заданная вручную на канвасе: «Ссылка на другую
    заметку…» → клик по цели; «Создать от этой заметки» → дочерняя нода + сплошная стрелка от родителя.
    Разворот/удаление из меню связи или клавишей Del.
14. **FR-14. Косвенные ссылки (P2, R15/R30).** Связь из `[[wikilink]]` в markdown-тексте, рендер после
    сохранения. Автодополнение при вводе `[[` по заметкам канваса (по заголовку + превью позиции),
    вставка `[[uuid|Заголовок]]`. Отображается пунктиром со стрелкой.
15. **FR-15. Битые ссылки (P2, R15/R30).** Косвенная ссылка на стёртую (purge) заметку → пометка «ссылка
    удалена» (серый пунктир), видна только имеющим доступ; ссылка на заметку в корзине — только ≥editor, с
    кнопкой «восстановить». Прямые ссылки удаляются вместе со стёртой заметкой.

### 6. Поиск

16. **FR-16. Поиск по канвасу (P1, R13/R19/R27).** Поиск по заголовкам и тегам доступных заметок;
    выпадающий список результатов (заголовок + совпавший тег); клик центрирует камеру. Пагинация (R19).

### 7. Файлы и вложения

17. **FR-17. Загрузка файлов (P2, R17/R31).** Вставка картинок в текст, аудио — аттачмент с плеером,
    `.md/.txt` (≤1 МБ) — содержимое в курсор редактора. Drop `.md/.txt` на канвас → новая заметка в
    точке дропа. Лимиты: картинки 5 МБ, аудио 25 МБ, текст 1 МБ. Валидация размера/типа (mime по
    содержимому) на клиенте и сервере; прогресс загрузки; ошибки — тост.
18. **FR-18. Хранилище (P2, R17).** Хранение в S3-совместимом хранилище (MinIO), uuid-ключи, presigned
    URL с TTL для чтения.

### 8. Доступ и публикация

19. **FR-19. Выдача доступа (P2, R16/R32).** Владелец канваса / автор заметки выдаёт доступ по email с ролью
    viewer/editor. Аккаунт есть — доступ выдаётся сразу (уведомление по почте), без принятия. Аккаунта нет —
    ожидающий инвайт, который превращается в доступ после регистрации и подтверждения email. Управление
    выданными доступами (смена роли, отзыв, отзыв ожидающего инвайта).
20. **FR-20. Публичность (P2, R16/R18/R32).** Канвас: переключатель «Только я / Публичная ссылка»
    (`…/shared/canvas/{slug}`, копирование URL; при выключении ссылка перестаёт работать). Заметка:
    переключатель «публичная / приватная». Shared-страницы — только чтение (зум/панорама/просмотр публичных
    заметок, рендер markdown), без контекстных меню и drag. Безопасный рендер чужого markdown (санитизация/XSS, R18).

### 9. Канвас-интерфейс (UI/UX)

21. **FR-21. Канвас (P2, R25–R27).** Бесконечный канвас: drag нод, resize, зум (Ctrl+колесо к курсору),
    панорама (колесо/Space+drag), пустые/загрузочные состояния (скелетон, empty-state, retry-баннер).
22. **FR-22. Контекстное меню (P2, R27/R30).** ПКМ: создание заметки в точке клика, «создать от этой
    заметки», связывание, теги, важность, видимость/доступ, архив, удаление; ПКМ по прямой связи —
    развернуть/удалить. Права: editor видит полное меню, viewer — только «Открыть».
23. **FR-23. Редактор заметки (P2, R28).** Панель с манифестом и Tiptap-редактором: H1–H3,
    bold/italic, список, код, ссылка, картинка-upload, автодополнение `[[`. Viewer — read-only рендер.

### 10. Локализация и поведение

24. **FR-24. i18n RU/EN (P3, R34).** Все строки через `t('…')`, словари `locales/ru.json` и
    `locales/en.json`; переключатель в шапке и профиле; выбор в localStorage, по умолчанию
    `navigator.language`.
25. **FR-25. Горячие клавиши (P3, R34).** Del (удалить выбранную ноду/связь, editor), Ctrl+F (поиск), Esc
    (закрыть меню/модалку/отменить связывание).
26. **FR-26. Уведомления (P2, R23/R34).** Toast: успех, ошибка сети, авто-refresh прозрачен,
    401 → редирект на `/login` с сообщением.
27. **FR-27. Лендинг (P3, R23).** Маркетинговая страница на `/`: описание продукта, кнопки «Войти» /
    «Регистрация» (авторизованному — «Открыть дашборд»), переключатель языка.

## Нефункциональные требования (NFR)

1. **Безопасность.** Argon2id для паролей; JWT-HS256; санитизация markdown и экранирование чужих
   `[[...]]`; политика 404 для недоступного; логирование без токенов/паролей; secret-scan в CI (R35).
2. **Производительность.** Граф одним запросом без N+1; индексы/CHECK в миграциях; пагинация
   `/canvases`, search и archive; rate-limit на nginx в проде (R36).
3. **Совместимость и окружение.** Чистый docker-compose (postgres, test-postgres, minio, mailpit, nginx+php-fpm);
   воспроизводимый dev-старт; зелёный CI (lint/typecheck/php-cs-fixer → unit → e2e).
4. **Контракт API.** `openapi.yaml` — источник правды; изменение API — вместе с обновлением спецификации
   в том же PR (ROADMAP, Этап 8). JSON — camelCase, БД — snake_case.

## Вне скоупа v1

Realtime-коллаборация, история версий заметок, полнотекстовый поиск по markdown-телу (Postgres FTS),
полноценная мобильная версия, автосохранение тела по таймеру, minimap, векторное рисование на канвасе,
размещение медиа прямо на канвасе без заметки, тёмная тема, фоновая чистка осиротевших объектов S3. → Бэклог v2.
