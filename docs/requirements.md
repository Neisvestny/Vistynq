# Vistynq — функциональные требования

Версия: 2026-09-17 · Источник правды по поведению: [`ui-ux.md`](ui-ux.md) и [`user-guide.md`](user-guide.md).
Связь с планом работ — [`ROADMAP.md`](ROADMAP.md), контракт API — [`api.md`](api.md) / `openapi.yaml`.

> **Vistynq** — веб-приложение для работы с заметками как с графом знаний: каждая заметка — нода на
> бесконечном канвасе, заметки связаны прямыми и косвенными ссылками, навигация строится на тегах,
> важности и наглядных связях.

## Роли и модель доступа

| Термин | Описание |
|---|---|
| Гость (аноним) | Видит только публичные shared-страницы (функциональность «Публичная ссылка»). |
| Пользователь | Зарегистрированный и подтверждённый email; имеет приватные канвасы и заметки. |
| Владелец канваса | Создал канвас; полные права: удаление канваса, инлайн-редактирование названия. |
| Editor | Приглашён с ролью `editor`; двигает/создаёт/редактирует любые заметки канваса. |
| Viewer | Приглашён с ролью `viewer`; только просмотр. |

Уровни доступа канваса и заметки: `private` (только создатель), `specific` (приглашённые по email,
роли viewer/editor), `public_link` (все, включая анонимов, только чтение). По умолчанию — `private`.
Эффективный доступ к заметке = max(доступ канваса, доступ заметки). Недоступный контент не отображается
никак (в т.ч. ссылки на недоступное) и отвечает 404.

## Функциональные требования (FR)

Приоритеты: **P0** — критично · **P1** — важно · **P2** — желательно · **P3** — на будущее.
Ссылки на задачи roadmap указаны в скобках `(R##)`.

### 1. Аккаунты и авторизация

1. **FR-01. Регистрация (P0, R09).** Регистрация по email, паролю (≥ 8 символов) и имени. Письмо со
   ссылкой подтверждения; без подтверждения аккаунт не активен. Повторная отправка письма («Отправить
   ещё раз»).
2. **FR-02. Вход и сессия (P0, R09/R10).** Вход по email + пароль (argon2id). Access-JWT (TTL ~15 мин)
   хранится в памяти клиента, refresh — в httpOnly cookie. Прозрачный авто-refresh сессии; при повторном
   401 — выход с сообщением «Сессия истекла». Логин ограничен rate-limit.
3. **FR-03. Безопасность сессий (P1, R10).** SHA-256-хэш refresh-токенов в БД, ротация с family-группой;
   повторное использование старого refresh отзывает всё семейство. OAuth/Cookie-флаги: HttpOnly, Secure
   (по env), SameSite=Lax.
4. **FR-04. Восстановление пароля (P1, R10).** «Забыли пароль?» → письмо → смена пароля. Сброс всех
   активных refresh-токенов пользователя.
5. **FR-05. Профиль (P1, R09/R14).** Просмотр и изменение имени; смена email с повторным подтверждением;
   аватар (загрузка через файловое хранилище, R22/R30). Выход отзывает токены браузера.

### 2. Канвасы

6. **FR-06. CRUD канвасов (P1, R11).** Список канвасов на дашборде (карточки: название, дата изменения,
   количество заметок, бейдж роли, бейдж «публичный»). Создание/открытие канваса. Название канваса
   редактирует только владелец. Удаление — только владелец, безвозвратное (hard-delete с каскадом, R11).
7. **FR-07. Загрузка графа (P1, R11).** Канвас целиком отдаётся одним запросом `/graph` (без N+1) с
   фильтрацией по правам (пользователь видит только доступные ноды и рёбра).

### 3. Заметки

8. **FR-08. Манифест и тело (P1, R12).** Заметка = манифест (заголовок, важность 1–5, теги,
   актуальность, доступ) + markdown-тело. Манифест редактируется формой (не как код), тело — редактором.
   Сохранение — по кнопке (автосохранение — не v1, ui-ux §3).
9. **FR-09. Позиционирование (P2, R26).** Позиция и размер ноды сохраняются после drag/resize (PATCH с
   дебаунсом ~500 мс) и восстанавливаются при перезагрузке.
10. **FR-10. Жизненный цикл (P1, R12).** soft-delete → панель «Удалённые» (восстановить в прежнюю
    позицию / purge необратимо). «Неактуально» → архив «Неактуальные» (вернуть / удалить).
    Пометка «ссылка удалена» у связанных заметок после purge — только для имевших доступ.

### 4. Теги

11. **FR-11. Теги канваса (P1, R13).** Теги локальны для канваса, имеют цвет. Создание, переименование,
    перекраска, удаление. Удаление тега затрагивает все помеченные заметки (с подтверждением).
12. **FR-12. Фильтры и подсветка (P2, R27).** Hover по тегу подсвечивает ноды (остальные — затемнены).
    Фильтр важности 1–5 (локально, без изменения БД) + тумблер «Показывать неактуальные».

### 5. Ссылки

13. **FR-13. Прямые ссылки (P2, R18/R29).** Связь, заданная вручную на канвасе: «Ссылка на другую
    заметку…» → клик по цели; «Создать от этой заметки» → дочерняя нода + сплошная стрелка от родителя.
    Разворот/удаление из меню связи или клавишей Del.
14. **FR-14. Косвенные ссылки (P2, R18/R29).** Связь из `[[wikilink]]` в markdown-тексте, рендер после
    сохранения. Автодополнение при вводе `[[` по заметкам канваса (по заголовку + превью позиции),
    вставка `[[uuid|Заголовок]]`. Отображается пунктиром со стрелкой.
15. **FR-15. Битые ссылки (P2, R18).** Ссылка на удалённую/purge-нутую заметку → пометка «ссылка
    удалена» (серый пунктир), видна только имевшим доступ.

### 6. Поиск

16. **FR-16. Поиск по канвасу (P1, R12/R27).** Поиск по заголовкам и тегам; выпадающий список
    результатов (заголовок + совпавший тег); клик центрирует камеру. Пагинация (R24).

### 7. Файлы и вложения

17. **FR-17. Загрузка файлов (P2, R22/R30).** Вставка картинок в текст, аудио — аттачмент с плеером,
    `.md/.txt` (≤1 МБ) — содержимое в курсор. Drop совокупного `.md/.txt` на канвас → новая заметка в
    точке дропа. Лимиты: картинки 5 МБ, аудио 25 МБ, текст 1 МБ. Валидация размера/типа (mime по
    содержимому) на клиенте и сервере; прогресс загрузки; ошибки — тост.
18. **FR-18. Хранилище (P2, R22).** Хранение в S3-совместимом хранилище (MinIO), uuid-ключи, presigned
    URL с TTL для чтения.

### 8. Доступ и публикация

19. **FR-19. Инвайты (P2, R31).** Приглашение по email с ролью viewer/editor. Если юзер не зарегистрирован
    — pending-инвайт, резолвится при регистрации по тому же email. Принятие/отклонение в колокольчике на
    дашборде. Управление выданными доступами (смена роли, отзыв).
20. **FR-20. Публичные ссылки (P2, R31).** Включение/выключение публичной ссылки (`…/shared/...`),
    копирование URL. Shared-страницы — только чтение (зум/панорама/просмотр заметок, рендер markdown),
    без контекстных меню и drag. Безопасный рендер чужого markdown (санитизация/XSS, R23).

### 9. Канвас-интерфейс (UI/UX)

21. **FR-21. Канвас (P2, R25–R28).** Бесконечный канвас: drag нод, resize, зум (Ctrl+колесо к курсору),
    панорама (колесо/Space+drag), пустые/загрузочные состояния (скелетон, empty-state, retry-баннер).
22. **FR-22. Контекстное меню (P2, R27).** ПКМ: создание заметки в точке клика, «создать от этой
    заметки», связывание, теги, важность, доступ, архив, удаление. Права: editor видит полное меню,
    viewer — только «Открыть».
23. **FR-23. Редактор заметки (P2, R29/R30).** Панель с манифестом и Tiptap-редактором: H1–H3,
    bold/italic, список, код, ссылка, картинка-upload, автодополнение `[[`. Viewer — read-only рендер.

### 10. Локализация и поведение

24. **FR-24. i18n RU/EN (P3, R33).** Все строки через `t('…')`, словари `locales/ru.json` и
    `locales/en.json`; переключатель в шапке и профиле; выбор в localStorage, по умолчанию
    `navigator.language`.
25. **FR-25. Горячие клавиши (P3, R33).** Del (удалить выбранную ноду, editor), Ctrl+F (поиск), Esc
    (закрыть меню/модалку/отменить связывание).
26. **FR-26. Уведомления (P2, R32/R14).** Toast: успех, ошибка сети, авто-refresh прозрачен,
    401 → редирект на `/login` с сообщением.

## Нефункциональные требования (NFR)

1. **Безопасность.** Argon2id для паролей; JWT-HS256; санитизация markdown и экранирование чужих
   `[[...]]`; политика 404 для недоступного; логирование без токенов/паролей; secret-scan в CI (R16).
2. **Производительность.** Граф одним запросом без N+1; индексы/CHECK в миграциях; пагинация
   search/archive/invitations/attachments; rate-limit на nginx в проде (R34).
3. **Совместимость и окружение.** Чистый docker-compose (postgres, minio, mailpit, nginx+php-fpm);
   воспроизводимый dev-старт; зелёный CI (lint/typecheck/php-cs-fixer → unit → e2e).
4. **Контракт API.** `openapi.yaml` — источник правды; изменение API — вместе с обновлением спецификации
   в том же PR (ROADMAP, Этап 8).

## Вне скоупа v1

Realtime-коллаборация, история версий заметок, полнотекстовый поиск по markdown-телу (Postgres FTS),
полноценная мобильная версия, автосохранение тела по таймеру, minimap. → Бэклог v2.
